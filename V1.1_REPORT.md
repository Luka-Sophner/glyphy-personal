Подготовлен существующий проект `E:\Codex\scripts\Glyphy APK` и его GitHub-копия. Версия приложения — **1.1.0**. Новый APK ещё не собран. Push и запуск GitHub Actions не выполнялись. Ключ подписи, Secrets и установленное приложение не изменялись.

## 1. Ошибка InvalidBlob

Путь изображения: выбор File → чтение исходных байтов → Blob URL для декодирования → отдельная PNG-миниатюра canvas.toBlob → MediaAsset → репозиторий → IndexedDB.

Прежний способ передавал File/Blob прямо в IndexedDB. Сообщение `DataError: Failed to write blobs (InvalidBlob)` соответствует сбою записи бинарного Blob в Chromium. Это не доказательство отсутствия поддержки Blob во всех Android WebView. Точную причину недействительности конкретного Blob на POCO — например, состояние файлового дескриптора — без воспроизведения и диагностики устройства установить нельзя.

Реализован обход именно этого пути записи: оригинал и миниатюра преобразуются в ArrayBuffer **до открытия транзакции записи**. В IndexedDB сохраняются байты, MIME, размеры, идентификатор и дата. Временные Android content URI и Blob URL постоянным хранилищем не служат. Оригинал не перекодируется и не сжимается. Миниатюра сохраняется отдельно.

Чтение через Dexie восстанавливает Blob для отображения, сохраняя MIME оригинала; миниатюра — PNG. Старые Blob-записи читаются без массового преобразования. Имя базы `glyphy` и схема v5 сохранены. Очистка базы при обновлении не добавлялась.

При ошибке транзакция откатывается; редактор сохраняет текст и подготовленное фото для повторной попытки. Предусмотрены понятные сообщения для переполнения хранилища и InvalidBlob. Изображения в логи не выводятся.

Источник происхождения ошибки: https://chromium.googlesource.com/chromium/src/+/refs/tags/128.0.6534.3/content/browser/indexed_db/indexed_db_transaction.cc
Правила транзакций: https://dexie.org/docs/Tutorial/Best-Practices

## 2. Совместимость данных и ZIP

Все рабочие пути записи медиа используют общий кодек: словарь, дневник, обложки групп, демонстрационные данные и ZIP-импорт. Глифы продолжают ссылаться на прежние ID и исторические снимки изображений. Сборка мусора удаляет изображение только после исчезновения всех ссылок.

Форматы ZIP v1 и v2 сохранены. Экспорт получает восстановленные Blob и записывает исходные байты; импорт переводит медиа в ArrayBuffer. Проверены восстановление старого словаря, полное восстановление модулей, разрешение конфликтов ID, merge, подтверждаемый replace и атомарный откат при ошибках. Очистка при replace существует только как явно подтверждаемая функция импорта, не как процедура обновления APK.

Обратная совместимость означает чтение старых данных новой версией. Установка старого APK поверх v1.1 с понижением версии и чтение нового формата старым приложением не гарантируются.

## 3. GitHub Actions

Сохранены оба рабочих исправления: `android-actions/setup-android@v4` и запуск тестов без несовместимого с Node.js 22 флага `--test-isolation=none`.

Конфигурация: Ubuntu 24.04, Node.js 22, Java 21, Capacitor 8.0.0, Android SDK Platform 36 и Build-Tools 36.0.0. Android-проект генерируется на Linux, затем конфигурируется и синхронизируется. Проверяются application ID, локальные ассеты и синхронизированный пакет. Release выравнивается zipalign, подписывается существующим alias `glyphy`, проверяется apksigner и загружается как **Glyphy-Android-APK** с контрольной суммой и build-info.

Добавлены автоматическая проверка сохранности рабочих параметров workflow и четыре проверки безопасной синхронизации Git. Ошибки не подавляются. Диагностика UI сохраняется отдельным артефактом.

Playwright теперь запускает отдельную production-сборку в `.verification/e2e-dist` на порту 5173. Это позволяет включить ранее пропускавшуюся проверку офлайн-перезагрузки PWA. Android-ассеты `dist` при этом не заменяются веб-сборкой.

Локальные `main` и сохранённый `origin/main` GitHub-копии находятся на `2d30cd1`; в истории есть оба исправления через сайт GitHub. Они сохранены в основном проекте и подготовленной копии.

Актуальность относительно сервера сегодня **не подтверждена**: GitHub-коннектор вернул 404, а `git fetch` остановился из-за недоступного сетевого подключения. Force push и изменения истории не выполнялись.

При отправке скрипт сначала делает fetch. Если найдены удалённые изменения, допускается только безопасный fast-forward с проверкой исходной версии каждого файла. При конфликте, независимых правках GitHub-копии или расхождении истории отправка останавливается. Дополнительно запрещена перезапись независимо изменённых файлов подготовленной копии и удаление изменённых устаревших файлов. Коммит и push требуют ввода `SEND PRIVATE`.

## 9. Готовность и следующие действия

**Исходники подготовлены к облачной проверке и сборке; полностью проверенным Android-релизом v1.1 пока не является.** Полный CI, подпись итогового APK и реальное обновление ещё предстоят.

1. В установленном Glyphy сохраните ZIP-копию данных.
2. Когда решите отправить обновление, запустите `send-github-update.bat`. Скрипт сначала проверит сервер; при конфликте остановится. Проверьте список и введите `SEND PRIVATE`.
3. Запустите **Build Glyphy Android APK**. **Setup Glyphy signing (ONCE) повторно не запускайте.**
4. Дождитесь всех проверок. При ошибке сохраните первый упавший шаг или UI-Diagnostics — проверки отключать не нужно.
5. Скачайте **Glyphy-Android-APK**, распакуйте и перенесите `Glyphy.apk` на телефон. Сверьте versionCode и certificateSha256 с предыдущей сборкой.
6. Установите как **обновление**. Приложение не удаляйте и его данные не очищайте. Если Android не предлагает обновление, сначала разберите несовпадение подписи или версии.
7. Проверьте старые записи и добавление новых фото по разделу 7.
