# Glyphy v1.1: безопасное обновление Android

Проект: `E:\Codex\scripts\Glyphy APK`.
Копия для отправки: `E:\Codex\scripts\Glyphy APK\GitHub-Glyphy`.
Репозиторий: https://github.com/Luka-Sophner/glyphy-personal

**Существующие два Secrets оставь без изменений. Не запускай Setup Glyphy signing (ONCE), не создавай другой ключ и не удаляй установленный Glyphy.** Android Studio, Java и Android SDK на Windows не нужны.

## Перед обновлением

Сделай экспорт ZIP через настройки установленного Glyphy и сохрани его отдельно от приложения. Если сохранение новой фотографии не работает, экспорт существующих данных всё равно стоит проверить. Не очищай IndexedDB и данные приложения для исправления ошибки.

Исходники v1.1 уже подготовлены. Редактировать нужно основной проект, а не копию `GitHub-Glyphy`.

## Отправь изменения

1. Убедись, что интернет и GitHub доступны.
2. Дважды нажми `send-github-update.bat` в основной папке.
3. Сначала скрипт проверит удалённые изменения. При неудачном соединении или конфликте он остановится до перезаписи файлов. Пришли текст ошибки — принудительная отправка не нужна.
4. Если проверка прошла, скрипт обновит безопасную копию и покажет список изменений и адрес репозитория.
5. Проверь адрес репозитория и список файлов. Введи в окне скрипта `SEND GLYPHY` и нажми Enter. Это разрешение отправить изменения. Пароли и токены в скрипт писать не нужно.

При запросе авторизации используй вход через предложенный браузер. Не перезаписывай удалённые правки вручную и не используй force push. Скрипт автоматически сохраняет односторонние изменения известных файлов; неоднозначные конфликты требуют согласования.

В Git отправляются исходники, конфигурация, штатные иконки, предоставленный шрифт и искусственная тестовая картинка. Пользовательская база, личные фотографии, ZIP-копии, APK и ключи не включаются.

## Нажми кнопку сборки

**Actions → Build Glyphy Android APK → Run workflow → main → Run workflow**.

Обычная сборка работает в публичном и приватном репозитории с двумя существующими GitHub Secrets. Для сборки в публичном репозитории после обновления workflow создай новый запуск через **Run workflow**.

Workflow устанавливает Node.js 22, Java 21 и SDK 36 / Build-Tools 36.0.0. Используется исправленный `android-actions/setup-android@v4`. После production build запускаются все тесты Node, Vitest и Playwright. Интерфейс проверяется на размерах 320×640, 393×852, 412×915 и 1365×768. Затем создаётся и синхронизируется Android-проект, APK подписывается прежним ключом, проверяются его подпись, ID, версия и встроенные локальные файлы.

Первая сборка после обновления дольше прежней: добавлены установка браузера и проверка интерфейса. Если тест или сборка завершились ошибкой, APK не публикуется. Открой первый красный шаг и пришли ошибку. Не удаляй проверки и не меняй ключ для исправления ошибки сборки.

При ошибке браузерных тестов может появиться artifact **Glyphy-UI-Diagnostics** с трассировками и скриншотами искусственных тестовых данных. Он хранится 3 дня.

## Скачай APK и обнови приложение

1. После зелёной галочки открой запуск.
2. Внизу в **Artifacts** нажми **Glyphy-Android-APK**.
3. Распакуй ZIP. Нужен файл **Glyphy.apk**, а не сам ZIP.
4. Передай APK на POCO, открой его файловым менеджером и при необходимости разреши установку из этого источника.
5. Нажми **Обновить**. Старый Glyphy не удаляй и данные не очищай.

Сохраняются `com.glyphy.personal`, прежние Secrets, alias `glyphy`, адрес хранилища `https://localhost` и имя IndexedDB `glyphy`. Android versionCode автоматически растёт по времени облачной сборки; versionName новой версии — `1.1.0`.

В архиве также будут `SHA256SUMS.txt` и `build-info.json`. Отпечаток `certificateSha256` должен совпадать с предыдущим APK, а `versionCode` должен быть больше.

## Проверь на POCO

1. Проверь старые фотографии, символы, глифы, дневник и обложки групп.
2. Добавь символ с фотографией из галереи и затем с камеры. Перезапусти приложение: фотография должна остаться.
3. Замени фотографию, удали ненужную тестовую карточку. Проверь глиф, использующий изображение символа.
4. Добавь и замени фотографии в дневнике, проверь обложки групп.
5. Создай ZIP-экспорт. Восстановление проверяй на тестовых данных; не заменяй единственную рабочую базу без проверенной резервной копии.
6. Проверь поиск, верхнюю безопасную область, конец списка и исчезновение градиента.
7. Открой клавиатуру в поиске, поверни телефон и быстро несколько раз открой и закрой меню.
8. Проверь запуск без интернета: компьютерный сервер не нужен.

Локальная проверка браузера: `npm ci`, `npx playwright install chromium`, затем `npm run test:e2e -- --workers=2`. Установку обновления и работу WebView проверяй на телефоне после сборки.

Подробности реализации и ограничения: `V1.1_REPORT.md`.

## Исправление авторизации send-github-update.bat

BAT использует один явно выбранный Git for Windows и Git Credential Manager с аккаунтом Luka-Sophner. GitHub Desktop использует свой Git и внутренний credential helper; вход в Desktop не авторизует автоматически обычный Git. Смена одного git.exe этого не решает.

Для проверки без отправки запустите в каталоге основного проекта:

```
send-github-update.bat --check
```

Если CLI ещё не авторизован, выполните:

```
send-github-update.bat --login
send-github-update.bat --check
```

В браузере выбирайте Luka-Sophner. Вводить токен или пароль в BAT/PowerShell не требуется. Учётные данные обслуживает Git Credential Manager через защищённое хранилище Windows, а не файлы проекта. Чувствительная трассировка отключается только на время сетевой команды, исходное окружение затем восстанавливается. Глобальные настройки Git и настройки Desktop не меняются.

Режимы --check и --login не копируют, не индексируют и не коммитят исходники; push не выполняется. Успех --check подтверждает доступ на чтение к main, но не проверяет право записи.

При обычном запуске батник получает изменения из GitHub, готовит копию из основного проекта и показывает изменения перед отправкой. Если в копии есть независимые правки, подготовка остановится с указанием файла. Подтверждение отправки — `SEND GLYPHY`.
