# Glyphy: APK через GitHub без Android Studio

Всё для облачной сборки подготовлено. Android Studio, Android SDK и Java на Windows не нужны. На GitHub используется Linux, Node.js 22, Java 21 и Android SDK 36 / Build-Tools 36.0.0. APK предназначен для установки напрямую, без Google Play.

## 1. Аккаунт GitHub

Если аккаунта нет, открой https://github.com/signup и зарегистрируй бесплатный личный аккаунт. Подтверди почту. Запомни способ входа и сохрани коды восстановления, если включишь двухфакторную защиту.

Для приватных репозиториев GitHub Free даёт ограниченные бесплатные минуты сборки и место для файлов. Для редких личных сборок обычно достаточно. Не подключай платное превышение лимита: при исчерпании бесплатного лимита можно дождаться его обновления. APK хранится в Actions 7 дней, поэтому скачивай его сразу.

## 2. Подготовь безопасную копию и создай приватный репозиторий

1. В папке `E:\Codex\scripts\Glyphy исходники` дважды нажми `prepare-github.bat`.
2. Появится папка `GitHub-Glyphy` внутри папки проекта. В ней только разрешённые исходники, штатные иконки и конфигурация сборки. Личная база, фотографии, ZIP-архивы, APK и ключи не копируются. Ничего пока не отправлено в интернет.
3. Установи **GitHub Desktop** с https://desktop.github.com/ и войди через браузер в GitHub. Это обычный клиент GitHub; Android-инструменты не устанавливаются. Git и Node.js на этом компьютере уже найдены.
4. В GitHub Desktop: **File → Add local repository → Choose…** и выбери `E:\Codex\scripts\Glyphy исходники\GitHub-Glyphy`. Выбирай именно эту папку, а не весь исходный проект.
5. Проверь список файлов во вкладке **Changes**. Там не должно быть личных изображений, выгрузок базы, архивов или ключей. Если Desktop попросит имя и email автора коммитов, укажи имя и приватный `noreply` email из GitHub → Settings → Emails.
6. В поле **Summary** напиши `Glyphy Android`, нажми **Commit to main**.
7. Нажми **Publish repository**, назови репозиторий `glyphy-personal` и **оставь включённым Keep this code private**. Нажми **Publish repository**. Это и создаст приватный репозиторий, и загрузит подготовленную копию.
8. Открой его через **Repository → View on GitHub**. У названия должна быть метка **Private**. Файлы `package.json`, `src` и `.github` должны лежать в корне репозитория, без дополнительной общей папки. Рабочая ветка — `main`.

Не загружай исходную папку целиком через браузер и не добавляй вручную новые личные файлы в `GitHub-Glyphy`. Эта папка — автоматически обновляемая копия для отправки; редактировать приложение продолжай в исходной папке.

## 3. Один раз настрой постоянную подпись

Приложение должно подписываться одним и тем же ключом при каждом обновлении. Для обычных сборок новый ключ никогда не создаётся. Понадобятся только два GitHub Secrets.

### 3.1. Сохрани пароль

1. Создай в менеджере паролей случайный пароль: желательно 24 и более латинских букв и цифр, минимум 16 символов. Сохрани его с названием «Glyphy: пароль подписи». Это отдельный пароль, не пароль аккаунта GitHub.
2. В репозитории открой **Settings → Secrets and variables → Actions → New repository secret**.
3. В **Name** впиши `ANDROID_KEYSTORE_PASSWORD`, в **Secret** вставь созданный пароль. Нажми **Add secret**.

### 3.2. Создай ключ в облаке

1. Открой вкладку **Actions**. Если GitHub предложит включить Actions, согласись.
2. Слева выбери **Setup Glyphy signing (ONCE)** → **Run workflow** → ветка `main` → зелёная **Run workflow**.
3. Дождись зелёной галочки и открой завершённый запуск. Внизу в **Artifacts** скачай **Glyphy-Signing-Backup-KEEP**. Этот архив доступен только 1 день.
4. Распакуй ZIP. Внутри будет `Glyphy-signing-backup.encrypted.json`. Это зашифрованная резервная копия ключа. Сохрани её в надёжном месте вне папки проекта и сделай вторую копию. Пароль из предыдущего шага тоже нужно сохранить: без него резервную копию не открыть.
5. В исходной папке дважды нажми `setup-signing.bat`. В окне выбора укажи распакованный `Glyphy-signing-backup.encrypted.json`.
6. Введи тот же пароль, который сохранил в `ANDROID_KEYSTORE_PASSWORD`. Символы при вводе не показываются. После успешного ввода ключ автоматически окажется в буфере обмена; писать команды и устанавливать Java не нужно.
7. На GitHub снова открой **Settings → Secrets and variables → Actions → New repository secret**. Имя: `ANDROID_KEYSTORE_BASE64`. В **Secret** нажми **Ctrl+V**, затем **Add secret**.
8. Вернись в окно скрипта и нажми Enter: буфер обмена очистится. Не вставляй содержимое ключа в чат, файлы исходников или обычные настройки репозитория.
9. После сохранения резервной копии удали завершённый запуск **Setup Glyphy signing (ONCE)** через меню `… → Delete workflow run`, чтобы убрать облачный архив раньше срока. Сам файл workflow оставь.

Готово: alias ключа всегда `glyphy`, пароль ключа совпадает с паролем хранилища. Отдельные Secrets для alias и второго пароля не нужны.

**Больше не запускай Setup для обновлений и не меняй два Secrets.** Когда ключ уже настроен, Setup специально останавливается с ошибкой. Если первый запуск прервался до настройки второго Secret, используй уже скачанный резервный файл; не генерируй другой ключ после начала использования приложения.

Если потребуется восстановить настройки в другом приватном репозитории: создай там `ANDROID_KEYSTORE_PASSWORD` со старым паролем, запусти локальный `setup-signing.bat` со старым зашифрованным файлом и вставь результат в `ANDROID_KEYSTORE_BASE64`. Облачный Setup повторять не нужно.

## 4. Нажми кнопку сборки

На GitHub: **Actions → Build Glyphy Android APK → Run workflow → main → Run workflow**.

Дождись зелёной галочки. Обычно это занимает несколько минут, первая сборка может быть дольше. Компьютер можно выключить после запуска: сборка идёт на GitHub.

Сборка сама устанавливает зависимости, собирает Vite в Android-режиме, создаёт Android-проект Capacitor, синхронизирует файлы, собирает release APK, подписывает его сохранённым ключом и проверяет результат. Если в репозитории есть `package-lock.json`, используется `npm ci`; пока его нет — `npm install`. Здесь создать lock-файл не удалось из-за недоступности npm. После первой успешной облачной сборки можно зафиксировать lock-файл для более воспроизводимых зависимостей; для запуска это не требуется.

## 5. Скачай готовый APK

Открой успешный запуск → внизу **Artifacts → Glyphy-Android-APK**. Скачай ZIP и распакуй его.

Внутри:

- `Glyphy.apk` — устанавливаемое приложение;
- `SHA256SUMS.txt` — контрольная сумма файла;
- `build-info.json` — версия, исходный коммит и отпечаток сертификата подписи.

Сохрани первый `build-info.json`. У последующих сборок `certificateSha256` должен оставаться тем же, а `versionCode` — увеличиваться. Номер версии для Android увеличивается автоматически по времени сборки. Скачанные APK не исчезают, даже когда GitHub удалит временный artifact.

## 6. Установи на POCO X6 Pro

1. Перед первым переносом данных сделай экспорт ZIP из Glyphy и сохрани его отдельно. Если пользовался браузерной версией, её данные сами в APK не перенесутся: импортируй ZIP через настройки приложения после установки.
2. Передай `Glyphy.apk` на телефон USB-кабелем или другим привычным способом. ZIP с GitHub устанавливать не нужно — нужен APK внутри него.
3. Открой APK в файловом менеджере. Если появится запрос «Разрешить установку из этого источника», разреши её для приложения, из которого открываешь APK. Названия пунктов в разных версиях HyperOS могут отличаться.
4. Нажми **Установить** и затем **Открыть**. При запросе проверки Play Protect дай ему проверить файл.
5. После установки при желании отключи разрешение установки из этого источника.

В APK встроены локальные файлы Glyphy. Компьютерный сервер не нужен. `https://localhost` в конфигурации — внутренний адрес локальных файлов Capacitor на телефоне, а не подключение к компьютеру. Работа на конкретном телефоне пока не проверена: после первой установки проверь запуск без интернета, словарь, дневник, изображения и экспорт ZIP.

## 7. Как выпускать обновления

1. Продолжай изменять исходный проект в `E:\Codex\scripts\Glyphy исходники`.
2. Дважды нажми `send-github-update.bat`. Он обновит безопасную копию и покажет список изменений и адрес репозитория.
3. Убедись на сайте GitHub, что репозиторий по-прежнему **Private**. Если список файлов верный, введи в окне `SEND PRIVATE` и нажми Enter. Это явное разрешение отправить изменения. Если Git запросит вход, используй вход через браузер; пароли и токены в скрипте не сохраняются.
4. Затем на GitHub нажми ту же кнопку **Build Glyphy Android APK → Run workflow** и скачай новый `Glyphy.apk`.
5. Перед обновлением сделай обычный экспорт данных Glyphy. Открой новый APK на телефоне и выбери **Обновить**. **Старое приложение не удаляй и его данные не очищай.**

Одинаковый ID `com.glyphy.personal`, постоянная подпись и возрастающий номер версии позволяют Android обновлять приложение с сохранением его данных. Схема базы и адрес локального хранилища этой настройкой не меняются. Резервный экспорт полезен и для обычных обновлений.

Если на телефоне уже установлен старый debug APK, подписанный другим ключом, Android не примет новый release APK как обновление. Сначала экспортируй данные из старого приложения. Для сохранения обновления без переустановки нужен именно старый ключ подписи; новый ключ не может его заменить. Если старого ключа нет, перенос возможен только через экспорт, переустановку и импорт, после проверки сохранённого ZIP.

Не редактируй автоматически созданную папку `GitHub-Glyphy` и не добавляй туда собственные файлы. Если изменил файлы прямо на GitHub, сначала **Fetch origin → Pull origin** в GitHub Desktop, затем согласуй эти изменения с исходной папкой. При ошибке `push rejected` не используй принудительную отправку.

## Если сборка красная

Открой запуск и первый красный шаг. Скопируй текст ошибки или пришли ссылку на запуск — содержимое Secrets присылать не нужно.

- **Check signing setup**: отсутствуют два Secrets или репозиторий не приватный.
- **Create encrypted signing backup**: пароль короче 16 символов, ключ уже настроен или ошибка создания ключа. Для обычных обновлений выбирай Build, а не Setup.
- **Install dependencies / Gradle**: проверь доступный лимит Actions; при временном сбое загрузки нажми **Re-run failed jobs**.
- **Sign and verify APK**: проверь, что BASE64 скопирован целиком и пароль соответствует исходному зашифрованному файлу. Не создавай новый ключ, чтобы исправить опечатку.
- **Run workflow не виден**: проверь, что `.github/workflows` находится в корне основной ветки `main` и Actions включены.
- **На телефоне «не установлено»**: проверь, что ставишь свежий APK, хватает места и старое приложение подписано тем же ключом. Не удаляй его, пока не сохранил экспорт.

## Что уже проверено

Подготовлены workflow, скрипт сборки и проверки APK, создание и восстановление зашифрованного ключа, безопасная копия для GitHub и отправка обновлений. Дизайн, анимации, код приложения и база данных не изменялись.

Локально прошли проверка TypeScript, обычная веб-сборка и 7 Android-тестов, включая шифрование ключа, отказ при неверном пароле и повторяемую конфигурацию облачной сборки. Проверен синтаксис Node.js и PowerShell-скриптов. Скрипт подготовки безопасной копии успешно выполнен повторно: создан локальный Git-репозиторий в `GitHub-Glyphy`, удалённый адрес не настроен. Workflow просмотрены на предмет порядка шагов, доступности Secrets, подписания и публикации artifact; реального выполнения на GitHub ещё не было.

Полная Android-сборка здесь не прошла: зависимости Capacitor отсутствуют локально, загрузка из npm блокируется; SDK и JDK 21 не устанавливались. APK фактически ещё не создан. GitHub Actions не запускался, исходники и личные данные не отправлялись. Реальную облачную сборку и установку можно подтвердить только после публикации приватной копии и настройки двух Secrets.
