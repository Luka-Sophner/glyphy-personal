## A. Когда APK уже собран

### Как установить

1. После успешной сборки откройте:

   `E:\Codex\scripts\Glyphy исходники\APK\Glyphy-debug.apk`

   Если файла нет или скрипт сообщил об ошибке, сначала выполните раздел B. Файл нельзя получить простым переименованием папки или ZIP.

2. Соедините POCO с компьютером USB-кабелем. Разблокируйте телефон. В уведомлении USB выберите «Передача файлов».
3. На компьютере откройте «Этот компьютер» → POCO → внутренний накопитель → Download. Скопируйте туда APK.
4. На телефоне откройте «Проводник» или «Файлы» → «Загрузки» и нажмите `Glyphy-debug.apk`.
5. Если Android попросит разрешить установку из этого источника, нажмите «Настройки» и разрешите установку именно этому «Проводнику» или приложению «Файлы». Вернитесь к APK и нажмите «Установить».
6. Дождитесь окончания, нажмите «Открыть». Иконка Glyphy появится в списке приложений. Если HyperOS не добавил её на главный экран, найдите Glyphy в списке и перетащите иконку на главный экран.
7. Разрешение установки для файлового менеджера после этого можно снова выключить.

Не нужно отключать защиту Android целиком. При предупреждении об угрозе проверьте происхождение и имя файла; не устанавливайте APK из неизвестного источника под видом этой сборки.

### Как перенести словарь, глифы и дневник

Данные браузера не появляются в Android автоматически: у установленного приложения своя база.

1. На компьютере откройте обновлённый Glyphy **по тому же адресу и в том же браузере, где находятся ваши данные**. Адрес, порт и профиль браузера имеют значение. Если видите пустой словарь, не создавайте в нём замену данным: вернитесь к привычному адресу.
2. Откройте настройки Glyphy и нажмите кнопку экспорта ZIP.
3. Сохраните ZIP на компьютере и оставьте эту копию. В обновлённой версии экспорт включает словарь, глифы, дневник, группы и связанные фотографии.
4. Перенесите ZIP на телефон в Download, так же как APK. Распаковывать ZIP не нужно.
5. В установленном Glyphy откройте настройки → импорт. В системном окне выберите ZIP из Download.
6. Проверьте количество карточек, глифов и записей в окне подтверждения. Для первого переноса выберите «Объединить» и подтвердите импорт.
7. Проверьте словарь, галерею глифов и дневник. Сравните несколько фотографий и дат с компьютером.

Старые ZIP, созданные прежней версией Glyphy, содержат только словарь. Новая версия их принимает, но отсутствующие в старом архиве дневник и глифы восстановить из него невозможно. Для их переноса создайте новый ZIP в обновлённой версии для ПК.

Для полной копии введён ZIP формата 2: прежний формат вообще не содержал глифов и дневника. Структура карточек и фотографий сохранена; добавлен файл с остальными данными. Одинаковая обновлённая версия на ПК и Android читает оба формата. Старое приложение полной копии читать не умеет. Если в базе только словарь, экспорт остаётся в прежнем формате 1.

«Объединить» сохраняет уже существующие записи с теми же идентификаторами. Это перенос и резервное копирование, а не автоматическая синхронизация изменений между телефоном и ПК. Чтобы полностью восстановить состояние из полной копии, существует режим «Заменить»: он заменяет также глифы, дневник и группы. Сначала экспортируйте текущие данные. Старый архив словаря при замене затрагивает только словарь.

### Как сохранить копию с телефона

В настройках нажмите экспорт. Glyphy подготовит ZIP и откроет системное меню Android «Сохранить или отправить». Выберите файловый менеджер с сохранением файла, если он предлагается, либо подходящее приложение для передачи архива. Для локального хранения не требуется облачный аккаунт.

После сохранения проверьте наличие ZIP в выбранной папке. Временный файл в кэше Glyphy не заменяет резервную копию: Android может очистить кэш. Не ограничивайтесь закрытием меню отправки.

Текущий предел ZIP — 128 МБ, одной фотографии — 40 МБ. Оригиналы фотографий сохраняются без уменьшения; отдельно создаются небольшие превью. Если большая база превысит предел ZIP, не удаляйте фотографии ради экспорта: потребуется отдельно расширить механизм резервных копий.

## B. Установка инструментов один раз

### 1. Android Studio

Официальная страница: https://developer.android.com/studio

Инструкция Google: https://developer.android.com/studio/install

Для этой конфигурации подходит **Android Studio Otter 2025.2.1 с Java 21**. Более новая версия тоже подходит, если на компьютере доступна Java 21. Если последняя версия Studio содержит другую Java, старую совместимую версию можно взять в официальном архиве: https://developer.android.com/studio/archive

1. Скачайте установщик Android Studio для Windows 64-bit. При необходимости выберите Otter 2025.2.1 в архиве.
2. Запустите установщик. Оставьте компонент Android Studio. Android Virtual Device — необязательный эмулятор: для получения APK он не нужен.
3. Оставьте обычный путь установки `C:\Program Files\Android\Android Studio`. Нажмите Next → Install → Finish.
4. При первом запуске можно выбрать Do not import settings. Вход в аккаунт для этой задачи не нужен.
5. В мастере установки выберите Standard, нажмите Next. Прочитайте условия предлагаемых компонентов; если согласны, выберите Accept → Finish.
6. Дождитесь окончания скачивания. Интернет нужен компьютеру для первой сборки, а не приложению на телефоне.

### 2. Компоненты Android

1. На стартовом экране Android Studio нажмите **More Actions → SDK Manager**. Если уже открыт проект: **Tools → SDK Manager**. В некоторых версиях это находится в **Settings → Languages & Frameworks → Android SDK**.
2. Во вкладке **SDK Platforms** поставьте галочку у **Android 16 / API Level 36**. Если список свёрнут, включите Show Package Details и выберите Android SDK Platform 36.
3. Во вкладке **SDK Tools** включите:
   - Android SDK Platform-Tools;
   - Android SDK Command-line Tools (latest);
   - Android SDK Build-Tools. Включите **Show Package Details** и отметьте именно **36.0.0**.
4. Нажмите **Apply → OK**, подтвердите загрузку и дождитесь завершения.
5. Оставьте обычное расположение SDK: `C:\Users\Luka\AppData\Local\Android\Sdk`. Скрипт найдёт его сам.

Если сборка позже пишет «JDK 21 не найден», а установлена другая новая Studio, проще установить указанную выше Otter 2025.2.1 из официального архива: она содержит нужную Java. Альтернатива в открытом Android-проекте: Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → Download JDK → Version 21. Оставьте предложенное место в `.jdks`: скрипт проверяет и эту папку. Java 17, уже установленная на компьютере, для этой Android-сборки недостаточна.

### 3. Получение APK

1. Откройте папку `E:\Codex\scripts\Glyphy исходники`.
2. Дважды нажмите `build-android.bat`.
3. Дождитесь окончания. Первая сборка может долго загружать зависимости. Не закрывайте окно, пока оно работает.
4. Скрипт сам установит зависимости, соберёт интерфейс, создаст официальную папку Android через Capacitor, добавит иконку, синхронизирует файлы, соберёт debug APK, проверит подпись и скопирует результат.
5. Успех — это сообщение «APK готов» и существующий непустой файл `APK\Glyphy-debug.apk`. При ошибке окно останется открытым, а краткая причина сохранится в `android-build-status.json`.

Не нужно вручную создавать проект в Android Studio, писать команды Gradle или редактировать файлы конфигурации. Зависимости Capacitor закреплены на совместимой ветке 8; требуются SDK 36 и Java 21. Первый успешный npm install создаст файл `package-lock.json`: сохраняйте его с проектом.

Если хотите открыть готовый Android-проект в Studio после первого успешного создания: нажмите **Open**, выберите папку `Glyphy исходники\android`, дождитесь синхронизации. Для обычных обновлений открывать Studio не требуется.

## C. Как обновлять Glyphy

1. Перед обновлением сохраните ZIP из установленного Glyphy.
2. Измените исходники в папке `Glyphy исходники`.
3. Дважды нажмите `build-android.bat` и дождитесь сообщения об успехе.
4. Перенесите новый `APK\Glyphy-debug.apk` на телефон. Откройте его и выберите обновление существующего приложения. Удалять Glyphy не нужно.

Скрипт сохраняет постоянное имя `com.glyphy.personal` и увеличивает номер успешной сборки. Сохраняйте `android-version.json` при переносе проекта на другой компьютер.

Для обновления без удаления данных должны совпадать имя приложения внутри Android и ключ подписи. Сейчас используется стандартная debug-подпись этого пользователя Windows. После первой успешной сборки ключ обычно находится здесь:

`C:\Users\Luka\.android\debug.keystore`

Сохраните его отдельную резервную копию в личном защищённом месте. Не добавляйте его в исходники, Git или публичные папки. На другом компьютере автоматически созданный debug-ключ может отличаться — такое обновление Android отклонит.

Debug APK подходит для первой личной установки. Для длительного использования лучше впоследствии перейти на постоянную release-подпись. В Studio это **Build → Generate Signed Bundle / APK → APK → Create new**. Ключ храните вне проекта, например в отдельной личной папке ключей, с надёжным паролем и резервной копией. Запишите пароль отдельно и не включайте его в Git. Подробности: https://developer.android.com/studio/publish/app-signing

Переход с debug-подписи на другой release-ключ обычно не позволяет обновить уже установленное приложение поверх старого. Сначала понадобится полная ZIP-копия, затем отдельный переход с восстановлением. Пока вы обновляете debug-сборки тем же сохранённым ключом, менять установленное приложение не требуется. Release APK этой работой не создавался.

## D. Частые проблемы

### APK не устанавливается

Проверьте, что копирование завершилось и выбран именно файл APK из папки проекта. Проверьте свободное место. Если на телефоне уже есть Glyphy с другой подписью, не удаляйте его сразу: сначала сохраните ZIP. Для обычного обновления соберите файл с прежним ключом.

### Android блокирует установку

Разрешите установку только тому файловому менеджеру, которым открыли свой APK. Не отключайте все системные проверки. Если это не обычный запрос разрешения источника, прочитайте причину предупреждения, проверьте происхождение файла и повторите сборку.

### Белый экран

Повторите сборку через `build-android.bat`: он проверяет наличие интерфейса внутри APK и отсутствие адреса dev-сервера. Убедитесь, что устанавливаете новый файл из APK, а не старую копию в Download. Обновите Android System WebView штатным способом, если установлен очень старый компонент. Не нажимайте «Очистить данные»: это может удалить локальные записи. Если проблема осталась, сохраните текст ошибки сборки и модель/версию Android для диагностики.

### Фотография не добавляется или не сохраняется

Проверьте свободное место и формат. Надёжнее всего JPEG, PNG или WebP. HEIC/HEIF зависит от поддержки декодирования на устройстве: если появляется сообщение о неподдерживаемом формате, выберите JPEG. Не закрывайте редактор до окончания сохранения. Работа камеры и системного выбора фото ещё требует проверки на POCO. Доступ ко всему накопителю приложению не нужен.

### Не работает импорт

Выбирайте исходный ZIP, созданный Glyphy, не распакованную папку. Предел — 128 МБ. В новом окне импорта проверьте показанные количества. Старый ZIP не содержит дневник и глифы. Полные архивы формата 2 открывайте обновлённым Glyphy и на ПК, и на телефоне. При ошибке текущая база не должна заменяться частично: восстановление записывает данные одной операцией.

### Не получается обновить APK

Чаще всего изменился ключ подписи. Верните прежний `debug.keystore` и повторите сборку. Не меняйте `com.glyphy.personal`. Сохраните `android-version.json`, чтобы номер новой версии не откатился назад. Не удаляйте установленное приложение и не очищайте его данные ради устранения ошибки обновления без полной ZIP-копии.

### Сборка не запускается

Окно скрипта показывает отсутствующий компонент. Если нет Node.js, установите LTS с https://nodejs.org/ и откройте скрипт заново. Если нет SDK или Java 21 — повторите раздел B. Если ошибка говорит ECONNREFUSED, ETIMEDOUT или о недоступности npm/Google Maven/Gradle, компьютеру нужен доступ к интернету для загрузки зависимостей. Не редактируйте код приложения ради сетевой ошибки.

Если Android Studio предложила принять лицензию установленного SDK, завершите это в SDK Manager. Если Gradle отдельно жалуется на национальные символы в пути, настройка `android.overridePathCheck=true` уже добавляется автоматически. При ошибке именно файлового инструмента можно скопировать проект в короткую папку латиницей, например `E:\Codex\scripts\Glyphy-Android`, и запустить тот же скрипт там. Сохраните ключ подписи и `android-version.json`.

## E. Проверка телефона после первой установки

Эта часть пока не выполнена: POCO и эмулятор к доступной среде не подключены.

1. Включите режим полёта и выключите Wi-Fi. Компьютер можно выключить.
2. Откройте Glyphy, создайте тестовую карточку с фотографией, найдите её поиском, измените значение и тег.
3. Создайте глиф из исходных символов и проверьте переход к карточке.
4. Создайте запись дневника с несколькими фотографиями, проверьте дату, просмотр разных пропорций и обложку группы.
5. Закройте Glyphy, уберите его из недавних приложений, откройте снова. Убедитесь, что записи и изображения остались.
6. Проверьте системную кнопку «Назад», поворот экрана, появление клавиатуры и доступность нижнего меню.
7. Экспортируйте ZIP, сохраните его вне кэша приложения и проверьте импорт на ПК. Не используйте режим «Заменить» для этой проверки без своей актуальной резервной копии.

Оболочка настроена на файлы внутри APK, без адреса сайта и без компьютера-сервера. База остаётся локальной IndexedDB. Однако полную автономность именно на Android можно подтвердить только после успешной сборки и этой проверки на телефоне.
